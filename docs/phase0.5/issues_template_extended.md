## テンプレート使用ガイドライン

### ラベル付けルール
- `enhancement`: 機能拡張
- `bug`: バグ修正
- `documentation`: ドキュメント更新
- `task-management`: タスク管理機能
- `incident`: インシデント管理
- `process-improvement`: プロセス改善
- `simulation`: シミュレーション機能
- `backend`: バックエンド開発
- `frontend`: フロントエンド開発
- `urgent`: 緊急対応必要
- `needs-triage`: 優先度評価待ち

### 優先度設定基準
1. **Critical**: システム全体に影響する障害、セキュリティ問題
2. **High**: 主要機能の障害、重要な機能要求
3. **Medium**: 一部機能の改善、マイナーなバグ
4. **Low**: ドキュメント更新、将来の拡張

### Issue管理フロー
1. **新規作成**: 適切なテンプレートを選択してIssueを作成
2. **トリアージ**: ラベル付けと優先度設定
3. **割り当て**: 担当者のアサイン
4. **対応**: 開発・修正作業
5. **レビュー**: プルリクエストの作成
6. **クローズ**: 完了確認とIssueクローズ

## 自動化設定

### GitHub Actions連携
- ラベル自動付与
- 優先度に基づく通知
- マイルストーン自動設定
- 依存関係チェック

### 定期メンテナンス
- Issueの定期見直し
- 古いIssueのクローズ
- テンプレートの更新
- 統計レポート生成
