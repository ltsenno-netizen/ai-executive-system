# Phase 1: AI Secretary Specification

## 1. 概要

フェーズ1のAI秘書は、AI幹部システムの初期段階として、管理職ユーザーの日常業務を支援する機能を集約したモジュールである。システム全体のオーケストレーションレイヤーの一部を構成し、インターフェースレイヤー（Web UI）およびデータ連携レイヤー（手動入力＋ローカルファイル）と連携する。Pythonベースのバックエンドで実装し、将来的な拡張（フェーズ2: 人材育成エージェント、フェーズ3: 予算・事業性エージェント）を前提とした構造とする。

## 2. システム全体像（レイヤ構造との関係）

- **インターフェースレイヤー**: WebベースのシンプルUI（将来的にReactなど）。ユーザーが「今週のレポートを出して」などの指示を入力し、AI秘書の出力を表示。
- **オーケストレーションレイヤー**: AI秘書の各機能（スケジュール管理、メンバー管理など）をPythonで実装。`src/backend/app/services/` にビジネスロジックを配置。
- **データ連携レイヤー**: フェーズ1では手動入力（テキスト/フォーム）とローカルファイル（CSV/JSON）。将来的にAPI連携（カレンダー、勤怠システム）を追加。

このレイヤ構造により、PoCとしてローカル完結しつつ、スケーラブルな設計とする。

## 3. フェーズ1の目的・ゴール

管理職ユーザーの業務負荷を軽減し、意思決定に集中できる環境を構築。具体的には、スケジュール整理、タスク管理、ドキュメント生成を通じて、日常業務の80%を自動化。短期ゴール（3-6ヶ月）：基本機能の実装で業務時間を20-30%削減。長期ゴール：思考の外部脳として戦略支援を提供し、フェーズ2・3への基盤を築く。将来的にユーザー固有のフローにチューニング可能。

## 4. ユーザーストーリー（一般的な1日の流れベース）

一般的な管理職の1日（9:00出勤、夕方退勤、会議多め）を基に、AI秘書が介入する流れを記述。将来的にインタビューで精緻化。

- **朝のルーチン (9:00-10:00)**: ユーザーが手動入力でタスク/スケジュールを登録。AI秘書が「今週の優先タスクTOP5」を生成し、UIに表示。
- **会議準備 (10:00-11:00)**: 会議アジェンダのドラフトをリクエスト。AI秘書がローカルデータを基に生成。
- **1on1フォロー (11:00-12:00)**: メンバー情報を手動入力。AI秘書が準備資料を作成。
- **昼休憩・戦略思考 (12:00-13:00)**: メモを入力。AI秘書がカテゴリ分けと問い提示。
- **午後の業務 (13:00-17:00)**: 進捗チェック。遅延アラートを発行。
- **夕方の振り返り (17:00-18:00)**: 「今日の振り返りレポート」を生成。

## 5. 機能一覧（カテゴリ別）

### 5.1 スケジュール・イベント管理
- 週間・月間イベントの自動整理（手動入力データから）。
- 「今週やるべきこと」レポート生成。
- 会議アジェンダドラフトと議事録要約。
- 1on1準備資料作成。

### 5.2 メンバー管理・フォロー
- 勤怠・コンディションのモニタリング（手動入力）。
- 「フォローすべきメンバー」レコメンド。
- メンバー課題・強みの整理。
- メッセージドラフト作成（トーン指定）。

### 5.3 タスク・進捗管理
- タスク一覧整理と優先度付け。
- 遅延リスク検知。
- 優先タスク提示と粒度調整。

### 5.4 ドキュメント生成・整理
- 会議テンプレート生成。
- 月次レポートドラフト。
- メモカテゴリ分け。

### 5.5 意思決定支援
- 最重要テーマ提案。
- リスク検知と意思決定ブリーフ。
- 判断のメリット・デメリット整理。

### 5.6 思考の外部脳機能
- アイデア整理。
- 「次に考えるべき問い」提示。
- 戦略補完分析。
- 追加: 行動ログ分析、心理安全性分析、業務棚卸し、振り返りレポート、文章学習、会議分析。

## 6. 入出力（フェーズ1時点の現実的な範囲）

### 6.1 入力
- **手動入力**: テキスト/フォーム経由（タスク、スケジュール、メモ、メンバー情報）。
- **ローカルファイル**: CSV/JSON（サンプルデータ: `data/samples/`）。
- **将来拡張**: API（カレンダー、Slack）。

### 6.2 出力
- **レポート**: Markdown/JSON（UI表示）。
- **通知**: コンソール/ログ（アラート）。
- **ドラフト**: テキスト（アジェンダ、メッセージ）。

## 7. 非機能要件（ローカルPoC前提＋将来拡張）

- **パフォーマンス**: ローカルPCで<5秒応答。将来的にクラウドでスケール。
- **セキュリティ**: データ暗号化（ローカル）。将来的にOAuth。
- **プライバシー**: 個人PC内完結。将来的に個人情報保護法準拠。
- **運用**: 手動起動。バックアップ手動。将来的に自動化・複数ユーザー対応。
- **ユーザビリティ**: CLI/Web UI。将来的にモバイル対応。

## 8. 将来の拡張（フェーズ2・3との接続）

- フェーズ2: 育成計画を人材エージェントに連携。
- フェーズ3: 予算データを事業性エージェントに統合。
- 技術: LLM統合で高度化。

## 10. Power Automate 連携（実装予定）

AI秘書の各 API を Microsoft Power Automate から自動実行し、  
毎日・毎週 Outlook メールで Masaharu に自動通知する。

### フロー構成

1. **毎朝 8:30** → フォローアップメンバー3名を通知
2. **毎週月曜 8:00** → 週次レポートを送付
3. **会議前日 18:00** → 会議アジェンダを自動生成・送付
4. **1on1 前日 18:00** → メンバー別準備資料を自動生成・送付

詳細は [power-automate-integration.md](./power-automate-integration.md) を参照。

## 11. 実装との対応（フェーズ1実装の詳細）

### スケジュール・タスク管理
- **状況**: 基本実装完了
- **実装**: `weekly_report_service.py` で `tasks.json` を読み込み、優先度でソート
- **出力**: TOP 5のタスク、優先度別集計

### メンバー管理・フォロー
- **状況**: スコアリングロジック実装完了
- **実装**: `recommendation_service.py` で以下を分析
  - 課題の多さ（課題数×2.0点）
  - 最近のタスク数（0件時の関心薄薄性×2.0点）
  - ロール変化（新規ロール×2.5点）
  - 強みの充実度（調整加算）
- **出力**: TOP 3のメンバー、優先度・理由・アクション案

### ドキュメント生成
- **状況**: テンプレートベースで実装完了
- **実装**: 
  - `agenda_service.py` → 会議アジェンダ生成
  - `oneonone_service.py` → 1on1準備ドラフト
- **出力**: Markdown/JSON形式でMail本文に埋め込み可能
